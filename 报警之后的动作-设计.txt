================================================================================
报警之后的动作 —— 设计
2026-10-29（覆盖 10-28 的版本，区别见第十一节）
================================================================================

这份文档记的是"报警报出来以后，设备自己做什么"。
报警怎么定义、怎么上报 Host、怎么入库不在这里（已经做完，见 skill 的 backend.md「报警」）。
SEMI E5 / E30 只管报警的上报（S5F1、Set / Clear、报出 / 清除事件）；报警之后停不停、怎么收场，
标准没有规定，由设备自己定。


================================================================================
一、一句话
================================================================================

报警报出来以后设备怎么收场，交给"策略"决定：
  - 平台按等级给四个现成策略，项目可以换、可以加；
  - 入库、推界面、报 Host 和触发策略走同一条路；
  - 每个等级只在报出来那一下做一次：把模块或整机切到现成的模式 / 状态，
    之后由调度和状态表自己挡住，不另做"报警挂着期间的限制"。


================================================================================
二、原则
================================================================================

    原则                          为什么
    ----------------------------  ----------------------------------------------------------
    一条路                        报出、清除只在报警元件里处理一次，界面、Host、设备看到的
                                  是同一件事、同一时刻
    按等级选策略，不看类别        类别（ALCD）是报给 Host 的分类码；"多严重、该怎么停"看等级
    平台写通用，项目只配置或扩展  停模块、停整机、切维护每台机都一样；关哪些阀、要不要先冲洗
                                  才是机型的事
    只在报出那一下做一次          维护、Error、整机 Error 这些现成的模式和状态本身就会挡住
                                  调度和开工，不用再记"挂着期间的限制"
    只能人工清，清了不自动恢复    阀保持原样，要人主动再开；人可能还在设备里
    策略只发请求                  报警常常是在模块锁里报出来的；真正的急停、停整机放到模块
                                  （整机）自己的扫描线程里做，不会互相卡住


================================================================================
三、整体流程
================================================================================

    定义      [Alarm] 写默认等级；machine.xml 可以按点改（比如急停那个 DI 改成 Fatal）
    报出      元件 RaiseAlarm / CheckAlarm，跟现在一样
    报警元件（一条路）
      ① 定归属：往上最近的模块；不在任何模块下的算整机
      ② 按等级取策略，调 OnRaised 发请求
      ③ 入库 → 推界面 → 报 Host（现成的）
    执行      模块（整机）在自己的扫描线程里照请求做：切维护 / 急停 / 整机停止
    清除      人工复位，走同一条路：入库 → 推界面 → 报 Host；不触发动作、不自动恢复

策略排在入库、推界面前面：它只发请求，几乎不花时间；报 Host 要走网络，放在后面，
Host 卡了也不耽误停机。

归属的例子：

    报警来自                                  算谁的
    ----------------------------------------  ----------
    Chamber.Chamber1 下的气缸、DI、轴         Chamber1
    LoadPort1 下的 E84、通讯                  LoadPort1
    Safety 下的急停、漏液（Safety 不是模块）  整机
    PLC、晶圆账、Job                          整机


================================================================================
四、四个等级（平台默认策略）
================================================================================

    等级    报出来那一下                              之后                      项目能改吗
    ------  ----------------------------------------  ------------------------  ----------------
    Warn    只报警                                    —                         不能，平台写死
    Light   所属模块切维护；不在模块下的，整机切      人处理完、复位，自己      能换
            Manual；模块没实现 IMode 的只报警         切回生产（整机切回 Auto）
    Heavy   所属模块急停（模块现成的 Abort），停完    复位、初始化后接着用      能换
            落 Error；不在模块下的，整机停止
    Fatal   整机停止（现成的 Stop），停完落整机       复位、全部初始化          只能继承它往上加
            Error

为什么这样就够：
  - Light：调度只用生产模式的模块。模块切到维护，手上的做完，不再派新活。
           注意维护模式下调度也不从它取片：做完的片留在里面，等切回生产才取走。
           机械手切维护，整机都搬不动，等于整机停止派活。
  - Heavy：模块在 Error，状态表不让发工艺动作，调度也不会派活。
           腔体在 Error 下手动页还能动气缸、轴（状态表故意留给恢复用）；阀只有 IO 页（工程师）能写。
  - Fatal：整机在 Error，状态表里 Auto 只能从空闲切，出 Error 要全部初始化
           （decisions.md 第 381 行留着要接的"Safety → Error"）。
  - 项目要关几个特定的阀，在自己策略的 OnRaised 里关一次。
  - 硬信号要一直锁住输出（门开、漏液就关阀），用 Io 现成的 SaftyIoInterlock：
    DI 触发就把 DO 强制到安全值，别人写会被拒，被改了会写回，解除后不恢复。


================================================================================
五、定级标准
================================================================================

    等级    什么样的报警                                  例子
    ------  --------------------------------------------  ------------------------------------
    Warn    提醒，不影响生产                              寿命快到、AI 预警带
    Light   这一片能做完，或者可以停下问人；              动作超时、设备报错、通讯断、流量超限
            但别再接新的
    Heavy   再动会伤设备或片，必须当场停这个模块          轴伺服报警、卡盘驱动报警、槽溢流
    Fatal   人身或全机安全                                急停、烟感（按点改）

等级在哪定：[Alarm] 写默认（不写就是 Heavy）；machine.xml 按点改。
DI、AI 是通用元件，一类只有一条报警定义，急停和门检测共用一个等级，所以必须能按点改。

现状：44 条报警，Warn 3 / Light 27 / Heavy 14 / Fatal 0，是当初按灯的颜色定的
（没写等级的默认 Heavy，比如所有 DI）。接上动作之前要按上面的标准逐条过一遍，
出一张"报警 → 等级 → 会怎么样"的表给用户定。
35021 现在开着报警的只有 8 个喷嘴流量 AI；Safety 下 14 个安全信号的报警都关着
（AlarmEnabled=False），要接整机停机得先定开哪些点。

这个标准也决定以后"动作卡住问人"怎么接：只有 Light 能停下来问人，
Heavy、Fatal 一律当场停、不问人。


================================================================================
六、写法：策略模式
================================================================================

    /// <summary>
    /// 报警处理策略
    /// </summary>
    public interface IAlarmStrategy
    {
        /// <summary>
        /// 报出来那一下做的事：只发请求、不等结果，平台放到模块扫描线程里执行
        /// </summary>
        void OnRaised(AlarmContext context);
    }

    AlarmContext：Alarm（刚报出来的这条报警）、Module（所属模块；不在任何模块下为 null，算整机）

平台：四个默认策略（只报 / 切维护 / 停模块 / 停整机），按等级用。
项目扩展：
  1. 机型工程里写一个类，实现 IAlarmStrategy，或者继承平台的再加东西；
  2. machine.xml 的 Alarm 节点上指过去，没指的等级用平台默认：

         <Setting Name="Alarm" Type="xyz.Elements.Elements.AlarmElement">
             <Value Name="HeavyStrategy" Value="xyz._35021.Module.Alarms.ChamberRinseStrategy" />
         </Setting>

  3. Fatal 只能配平台的停整机或它的子类，配错开机就报错。

举例（35021：腔体报重报警先冲洗再停，别的模块照平台的停）：

    public class ChamberRinseStrategy : StopModuleStrategy
    {
        public override void OnRaised(AlarmContext context)
        {
            if (context.Module is ChamberModule chamber)
            {
                // 放到腔体自己的扫描线程里做；RinseThenStop 是机型自己的动作
                context.Post(() => chamber.RinseThenStop());
                return;
            }

            base.OnRaised(context);
        }
    }

规矩：OnRaised 里只发请求、不等结果、不拿别的模块的锁。动作失败的报警是在模块锁里报的
（BaseChamberModule.RaiseActionFailedAlarm 的注释写着"别去拿别的模块的锁"）。
Post 这类发请求的方法，做平台那一步时加到 AlarmContext 上。


================================================================================
七、生产 / 维护（IMode）
================================================================================

  - 模块的"auto / manual"就是生产 / 维护：IMode（Mode、SetProduction、SetMaintenance）。
  - 这是能力接口，要的模块自己实现，不放基类（用户 10-29："做成接口，不要放在基类里"）：
    站点（LoadPort、腔体、Buffer、对准器）、机械手、供液（10-29 加）。
    整机没有，它有自己的 Auto / Manual（自动派单开关，开 Job 要在 Auto 下）。
  - 供液：没有手动页，开机就是生产；维护时腔体不能用它起新工艺，正在做的照常；
    切换走 SupplyService（SetProductionAsync / SetMaintenanceAsync）。
  - 界面上模块的模式显示"生产 / 维护"；LoadPort 页上的"自动 / 手动"是 E87 的交接方式
    （搬运车经 E84 / 人工放取），不是这个。


================================================================================
八、复位和忽略
================================================================================

  复位（报警栏、顶栏，现成的）
    报警清掉。Light 切到维护的模块要人自己切回生产；Heavy 停过的模块还在 Error，
    要在模块上复位、初始化（急停过的设备要人确认，故意不自动）；Fatal 要全部初始化。
    阀不会自己打开。

  忽略（待做）
    这次放过：只给 Warn、Light 的信号类报警，工程师能点。报警清掉，信号回到正常之前不再报，
    下次再出现照报；历史里记一行是谁忽略的。Heavy、Fatal 不能忽略。


================================================================================
九、不做的
================================================================================

  - 不做"报警挂着期间的限制"（不投新片、锁安全阀、挡开工）：现成的模式和状态已经管住。
  - 不做配置化的"条件 → 动作"规则表；硬信号锁输出用 Io 现成的 SaftyIoInterlock。
  - 模块之间不互相调；跨模块的事归整机，真有需求再写。
  - 报警清除不触发动作，不自动恢复。
  - 类别（ALCD）只上报 Host 和界面显示，不参与控制。
  - 以后再做：动作卡住问人（重试 / 忽略 / 中止）、蜂鸣器静音、供液手动页（切回生产的按钮）。
