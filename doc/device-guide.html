LoadPort · 总览

LoadPort 在系统里管什么

LoadPort（装载口）上放 FOUP（片盒）。它要做的事：夹紧、开门、Mapping（扫出每个槽有没有片），读载具号，然后把片交给机械手取放；干完关门，等人或天车把盒子拿走。接了天车时要跟天车走 E84 交接，接了 Host 时要跟 Host（EAP 的 E87）核对载具。

配置：sc.xml 和 EC

装机、接线、结构性的进 sc.xml（改了重启生效）；现场要调的超时、开关进 EC（ec.xml，在 设置 → EC 设置 里改，下一拍就生效）。sc.xml 只有一份源文件，编译时拷到宿主 bin 下，运行时读的是 bin 那一份。

一个 LoadPort 节点长这样

<Setting Name="LoadPort">                       <!-- 分组节点，名字不进路径 -->
  <Setting Name="LoadPort1" Type="xyz._35021.Module.Loadport.LoadPortModule">
    <Value Name="SlotCount" Value="25" />
    <Value Name="PresenceSource" Value="Query" />   <!-- 在位以状态查询为准，见"在位判断" -->
    <Setting Name="Driver" Type="xyz.Components.Components.FcdLoadPortComponent">
      <Value Name="CommType" Value="Serial" />
      <Value Name="PortName" Value="COM2" />
      <Value Name="BaudRate" Value="9600" />
      <Value Name="Parity" Value="None" />
      <Value Name="DataBits" Value="8" />
      <Value Name="StopBits" Value="One" />
    </Setting>
    <Setting Name="RFID" Type="xyz.Components.Components.FcdRfidComponent">
      <Value Name="PortName" Value="COM6" />
      <Value Name="IdStart" Value="0" />
      <Value Name="IdLength" Value="16" />
    </Setting>
    <Setting Name="E84" Type="xyz.Modules.E84Component">
      <Value Name="IsEnable" Value="False" />        <!-- 本机没接天车 -->
      <Value Name="DiValidIndex" Value="34" />

    </Setting>

</Setting>

Type 写类型全名，装配时按全名在运行目录和 Modules\ 下的 DLL 里找，找不到开机就报错。节点名（LoadPort1）就是模块名：界面页签、推送 token、晶圆账位置、EC 路径都用它。

常用改法

  • 加一个 LoadPort：复制 LoadPort1 节点改名 LoadPort3、改串口；机械手 Stations 加同名站点；重启。主界面页签、手动页按系统设置的名单自动多出一个。
  • 停用一个口：IsEnable=False。
  • 换品牌：改 Driver 节点的 Type（换成那个品牌的驱动壳），通讯参数按新设备填。模块和界面都不用动。
  • 本机没接天车：E84 节点 IsEnable=False。装了但临时不交接，用 EC E84Enabled。
xyz.Drivers / Communication · Loadport · Loadport/FCD

驱动与通信

xyz.Drivers 是纯协议和通讯，不引用任何别的工程（只用串口包）。机械手、RFID 的驱动也在这里，共用同一套通讯层。

类管什么
SerialCommunication / TcpCommunication串口、网口：Connect / Close / Send / Receive。出 IO 错误自己关掉连接
FrameCommunication用品牌的帧编解码包壳、拆帧；起接收泵收包。一次打开一轮接收泵，旧泵出错只停自己那一轮，重连不会被它搅乱
LoadPortDriverBase在途表（同名指令一次一条）、发送队列、帧路由（先问在途指令"是不是你的"，没人认的当设备主动事件）、作废 Abandon / AbandonAll
LoadPortCommand一条指令：Key（在途槽位）、BuildMsg、ParseMsg、完结后 Response（厂商无关结果）
LoadPortStatus状态快照，开关量都是 Is 开头：IsPresent、IsPlaced、IsDoorOpen、IsDoorClosed、IsDeviceAlarm……
FcdLoadPortDriver / Fcd*CommandFCD 品牌：主动事件 PODON / PODOF，各条指令

FCD 一帧长什么样

s00帧头 + 地址
MOV:CLOAD类型 : 指令名[/数据]
;结束符
\r分隔

类型前缀：GET 查询、MOV 动作、SET 设置。回复：ACK 受理（查询类 ACK 就是完结）、INF 完成或主动事件、ABS 异常完成、NAK 拒绝。

设备上报—INF:PODON / INF:PODOF放上 / 拿走事件

状态串：第 1 位在位、第 2 位到位、第 8 位报警，第 43 / 44 位是门开 / 门关（字符 O）；其余位等协议手册确认，原文留在 LoadPortStatus.Raw。

落到晶圆账时：有片记正常片，交叉、叠片照记，认不出的按"有片、状态不明"记。记成空而实际有片，机械手会往上放，那是撞片，所以宁可多记。

在途指令和作废

  • 同名指令同一时间只能有一条在途，前一条没完结，再发会被拒（Submit 返回 false，动作判 loadport.command_rejected）。
  • 回复丢了，这条就一直占着在途位。所以要作废：状态查询超时作废这一条；动作没做成（失败、超时、被中止）作废全部；关连接、重连时作废全部。
  • 作废的指令以失败落终态，等它的人马上醒。它的回复要是迟到了，没有在途指令认它，当无主帧丢掉。

加一个新品牌的 LoadPort

  1. 在 xyz.Drivers/Loadport/<品牌>/ 写协议常量、帧编解码（实现 IFrameCodec）、驱动（继承 LoadPortDriverBase，重写 ParseSpontaneousEvent 认出放上 / 拿走）、每条指令（继承 LoadPortCommand）。
  2. 状态查询把品牌状态串翻成 LoadPortStatus 的 Is* 位；Load 把品牌槽位串翻成 SlotState。上层只认这两样。
  3. 在 xyz.Components/Components/Drivers/ 写品牌壳，继承 LoadPortDriverComponent，只写 CreateDriver 和 9 个 Create* 指令工厂，类上加 [Component]。
  4. sc.xml 里 Driver 的 Type 换成这个品牌壳。模块、服务、界面都不用改。
xyz.Components / Components / Drivers

驱动组件、RFID 和断线重连

驱动组件是挂在 LoadPort 节点下的子组件，把 sc.xml 的通讯配置、驱动的打开关闭、重连包起来，给模块一个统一的触发口。它不自己起线程，OnScan 跟着父模块的扫描线程跑。

组件给模块用的
LoadPortDriverComponentLoad()、Unload()、Home()、Clamp()、Unclamp()、Stop()、ResetDrive()、QueryStatus()、QueryVersion()：发一条指令，受理了返回指令对象，被拒返回 null；DeviceEvent 设备主动事件；Abandon / AbandonAll
FcdLoadPortComponentFCD 品牌壳，只决定造哪条 FCD 指令
RfidDriverComponent / FcdRfidComponentStartReadCarrierId() 只发起，结果模块每拍 GetCarrierIdResult() 取；读码超时（EC）作废在途
DriverReconnectorLoadPort 驱动和 RFID 共用的断线重连

断线重连怎么走

  • 组件 Open 过才管（装机停用的不管），Close 以后不再重连。
  • 发现断了先记一条告警"通讯断开，每 N ms 重连一次"，之后按 EC ReconnectIntervalMs 在后台先关后开。关的时候在途指令全部作废、旧的收发任务收掉。
  • 重开放在后台做：网口连不上时 Connect 要卡好几秒，不能卡扫描线程。连上了记一条"通讯恢复"，中间重连不上不再刷日志。
  • RFID 读头连不上不连累 LoadPort：照常开 LoadPort 驱动、登记晶圆账槽位，只是先读不了码。

载具、Mapping 落账、报警

  • 载具对象 CarrierInfo：载具到了建、拿走清。带三组状态：ID 认定到哪步、槽图认定到哪步、取放到哪步。接了 EAP 时由 E87 把 Host 的结果写回来。
  • Mapping 落账：Load 成功后这个端口的晶圆账整篮重建；读码比 Mapping 晚回来时，载具号会补到这一篮的片上。
  • 报警：初始化超时、受控停止、LoadPort 设备报警（状态查询的报警位亮就报）。报警只能人工复位清，设备恢复了也不自动清。

站点环和端口搬运状态

  • LoadPort 是机械手的站点，待命态是 Loaded（门开着才能取放）。机械手第一次来取放，载具进 IN ACCESS（E87 的"在取放"）。
  • LocalTransferState 是端口自己判的搬运状态，E84 和 E87 都看它：停用、下线、没初始化、出错 → 停用；在忙 → 挡着；空闲没盒 → 等送盒；空闲有盒且这一盒干完或中断 → 等取走。

机型要改某个动作

在机型的 LoadPortModule 里重写那一个，其余照用平台的。例：这台机门禁没关好不让开门（返回 null 就是拒，服务回 module.action_rejected）：

[Component(description: "XXXXX LoadPort 模块")]
public class LoadPortModule : BaseLoadPortModule, ILoadPort
{
    /// <summary>
    /// Load 之前先看门禁：没关好不开门；关好了走平台的 Load。
    /// </summary>
    public override ModuleOperation? Load()
    {
        // IsInterlockClosed 是这个机型自己写的检查（比如读一个 DI）
        if (!IsInterlockClosed())
        {
            return null;
        }

        return base.Load();
    }
}

要加一个单条指令的新动作，可以直接用 new LoadPortCommandOperation("动作名", () => 发指令, () => 超时, 成功后要做的事)。

BaseLoadPortModule · SenseCarrierArrived / CheckCarrierPresence

在位判断：载具到了没有

三个名字别弄混：

名字是什么在哪
IsPresent状态查询的原始位：在位（端口上压着东西）LoadPortStatus、LoadPortDto
IsPlaced状态查询的原始位：到位（放平、卡进定位销）LoadPortStatus、LoadPortDto
IsCarrierArrived后台判出来的"载具到了"。到达、拿走、E84、Job、回片、E87、界面"在位"用的都是它模块、ILoadPort、LoadPortDto

SC PresenceSource 二选一

Query（默认）在位 IsPresent到位 IsPlaced判断
亮亮载具到了
灭灭拿走了
一亮一灭放了一半、没放正、正在拿：不算变化，保持原判断
查不到没连上、查询超时：保持原判断

Event：只认设备主动上报，PODON 算放上，PODOF 算拿走，状态查询说什么都不管。

怎么选Query 能自己对上：开机时盒子已经在端口上、丢过一个事件、断线期间换了盒，下一次查询都能认对；读错一位不会被当成拿走，要两位一起错才会。它靠状态查询一直在跑。Event 反应快，但开机已在端口上的盒子、断线期间的变化认不出来。

到达、拿走的时候做什么

只在扫描线程上判：这一拍判出来的跟上一拍不一样，才算放上或拿走。

  • 到达：建载具对象 → 回调 E87 CarrierArrived → 报 GEM 事件 FoupArrived → 自动读码（AutoReadCarrierId）。
  • 拿走：清载具号、槽图、载具对象 → 晶圆账清掉这个端口的片 → 回调 E87 CarrierRemoved → 报 FoupRemoved。

一拍扫描与线程

每个模块一条自己的扫描线程，50 ms 一拍。LoadPort 一拍按这个顺序做：

  1. 子组件：驱动组件看要不要重连，RFID 推读码步进机。
  2. 挂着的动作往前推一步（在 OperationGate 锁里）；做完就收尾：落状态 → OnOperationCompleted → 叫醒等结果的人。
  3. PollStatus：查设备状态，一次一条 GET:STATE，超时作废重发。
  4. CheckCarrierPresence：判载具到达 / 拿走。
  5. StepE84：推一步 E84 握手。
  6. CheckCarrierIdRead：收读码结果。
  7. CheckDeviceAlarm：设备报警位亮就报警。
  8. PublishState：跟上次比有变化，就推给界面。

写代码时守的规矩

  • 扫描线程里不等待：动作写成步进机，每拍做一步就返回。在里面 Sleep 或等结果，整个模块这一拍就卡住了（状态查询、在位、E84、推送全停）。
  • 发起和等待分开：Begin 只挂上动作（瞬间），阻塞等的是服务层的 WaitReply，最长等到动作超时。
  • 改模块状态只有三处：Begin、CompleteOperation、TransferStep，都在 OperationGate 锁里。别的线程不拿锁读到的只是某一刻的快照，真去做时会在锁里再查一遍。
  • 锁里不做慢事：OnOperationCompleted 和动作的每一步都在锁里跑；EAP 回调只放进队列，由专用派发线程发。

EAP 对接：E87 载具管理、E84 天车交接

设备侧给 EAP 开三个口子，EAP 只做 SECS 翻译，真正的状态只在设备侧存一份：

口子是什么LoadPort 上
命令接口EAP 和本地界面调同一个接口、过同一套检查ILoadPort（Load、SetCarrierId、UpdateCarrierStatus……）
上报口设备侧发生了什么，按发生顺序回调给 EAPE87Callback、E84Callback
反查口要 Host 拿主意的事，设备侧问它；为 null 时按本地规则E84Provider（现在能不能交接、往哪个方向）

没接 EAP 时这三个都是 null，LoadPort 照常跑。

接了 EAP 时一个盒子的路线（E87）

  1. 放上 → 读码。有预告（Bind / CarrierNotification）且号对上，设备认定（#6）；没预告，等 Host ProceedWithCarrier（#3 → #8）。
  2. ID 认定后自动 Load（SC AutoLoad）→ 读槽图。跟 Host 给的一样，设备认定（#13）；否则等 Host（#14 → #15）。
  3. 槽图认定就是"料到了"：Host 给的片号写进晶圆账，通知 E90 建片对象。
  4. 机械手第一次来取放 → 载具 IN ACCESS（#18）。
  5. CJ 完成 → NoteCarrierComplete → 干完（#19）→ 自动 Unload（SC AutoUnload）→ 端口等取 → 拿走（#21）。

Host 的载具动作走 S3F17，端口动作 S3F25，改存取方式 S3F27，都要 ON-LINE REMOTE。

E84（天车交接，IO 版）

  • 握手：天车选中本口 → L_REQ / U_REQ → TR_REQ → READY → BUSY → 盒子放上 / 取走 → COMPT → 撤信号。任一段超过 TP1~TP5 就把输出全灭、锁住，等人工 Retry 或 Complete。
  • 端口每拍把 Auto/Manual、搬运状态、载具到没到交给 E84，能不能交接由 E84 自己判：要 Auto、在线、搬运状态是等送或等取才交接。
  • SC IsEnable 管装没装（False 时端口当没有 E84）；EC E84Enabled 管装了以后交不交接。
xyz.Modules / Job · Transfer · xyz.Components / System / WaferManagerComponent

跟 Job、搬运管理、全部回片的关系

  • Job：建 Job 要求载具能取片（载具到了，并且是 Loaded 或正在被机械手服务）；取片顺序看 EC PickOrder；CJ 结束时调 NoteCarrierComplete，告诉 LoadPort 这一盒干完了；载具拿走（或换了一个）以后，完成的 CJ 才删。
  • 搬运管理：LoadPort 是一个站点，取放片走站点环，待命态是 Loaded；整机 Stop 时由搬运管理收场。
  • 全部回片：片回它来源 LoadPort 的同号槽，要求那个口载具到了且是 Loaded；片记着的载具号跟现在的对不上就不放。
  • 晶圆账：Open 时登记这个口的槽位；Load 成功整篮重建；载具拿走清掉；重启后不恢复 LoadPort 上的片，以开机 Mapping 为准。

新机型接入 LoadPort

LoadPort 的动作、状态查询、在位、重连、推送都在平台。新机型通常只要一个空的机型类加 sc.xml，一行 LoadPort 逻辑都不用写；机型独有的东西才写进机型类。

  1. 建机型后端工程

    照 xyz.35021/Service/xyz.35021.Module：命名空间 xyz._<机型>.*（数字开头前面加下划线），引用 xyz.Modules、xyz.Shared；编译后 DeployToHost 把 DLL 拷到宿主 Modules\<机型>，宿主启动时按目录扫描加载。

  2. 建 LoadPort 机型类

    空类就能用，留着放这个机型独有的：

    using xyz.Components.Attributes;
using xyz.Components.Interfaces;
using xyz.Modules;

namespace xyz._XXXXX.Module.Loadport;

/// <summary>
/// XXXXX 机台 LoadPort 模块：动作都用平台的，跟平台不一样的再重写。
/// </summary>
[Component(description: "XXXXX LoadPort 模块")]
public class LoadPortModule : BaseLoadPortModule, ILoadPort
{
}

  3. 写 sc.xml

    LoadPort 分组下一个口一个节点，Type 写机型类全名；Driver 挂品牌壳（FCD 用 FcdLoadPortComponent），有读头挂 RFID，有天车挂 E84（没接就 IsEnable=False），PresenceSource 按设备选。写法见"配置"。

  4. 机械手站点表加上这几个口

    机械手节点 Stations 下加同名站点：Number、Y、Direction、Arms。没加的口机械手去不了，流程配方里也选不到。

  5. 品牌不是 FCD

    先照"驱动与通信 → 加一个新品牌"写驱动和品牌壳，sc.xml 的 Driver 换成新品牌壳。

  6. 客户端

    手动页 Manual.LoadPorts 由机型注册：照 35021 的 LoadPortsManualView + LoadPortsManualViewModel（一页按 LoadPort 名单放平台的 LoadPortManualControl），在机型的 IClientModule.Register 里注册成这个键。主界面 LoadPort 页签、调度图卡片不用写，照系统设置和机械手站点表自己生成。

  7. 有特殊动作再重写

    在机型类里重写那一个动作（见"模块"一节的例子）。单条指令的新动作直接用 LoadPortCommandOperation。

  8. 验证

    编译整个 sln；跑 OperationWaitSmoke、JobSmoke；上机看日志："通讯恢复"、"Mapping 落账：N 片"，有没有"状态查询超时""通讯断开"。
